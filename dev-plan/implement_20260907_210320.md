# implement_20260907_210320.md

작성 일시: `2026-09-07 21:03:20 KST`

이 문서는 이번 개발의 범위를 고정하고, 구현이 목적 밖으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

ThreadFlow OS의 기본 생성 경로를 loopback Codex OAuth Provider Proxy 계약으로 정렬한다. 동일 생성 요청의 중복 LLM 호출, Provider 출력의 인증값·개인 경로 유출, 승인 후 다른 본문·근거·이미지가 Threads 수동 전달에 사용되는 무결성 위험을 차단한다.

## 개발 범위

- `Codex OAuth Provider Proxy`를 Gateway의 기본 Provider로 선택하고, 기존 App Server 직접 연결은 명시적 `direct` 개발 모드로만 유지한다.
- Proxy loopback URL, caller ID, 절대경로 secret 파일, `0600`, timeout, output 상한, readiness 및 취소를 검증한다.
- 브라우저·서버 공통 canonical JSON/SHA-256 요청 지문과 `Idempotency-Key` 계약을 추가한다.
- Provider 출력은 SSE/DB/UI에 도달하기 전 token·JWT·인증 필드·개인 로컬 경로를 검사하고 차단한다.
- 승인 본문·소스·위험 snapshot·선택 이미지 hash를 묶은 credential-free 승인 snapshot과 수동 전달 패키지를 생성·검증한다.
- 사용자가 Proxy 관리 세션과 직접 OAuth 모드를 혼동하지 않도록 연결 상태 문구를 정확히 표시한다.

## 제외 범위

- 19개 SNS 채널, 이미지 생성, 캠페인 지표, 실제 자동 게시, 새 Meta API 흐름.
- Proxy 서버 자체의 설치·운영·OAuth 계정 공유. 이 저장소는 안전한 caller로서의 client만 구현한다.
- 기존 DB v4 테이블 재설계, 편집 레이아웃 리디자인, 검수 기준 완화.
- Proxy 외부 실행값이 없는 상태에서 실 OAuth 생성 성공을 주장하는 것.
