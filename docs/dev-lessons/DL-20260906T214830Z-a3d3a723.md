# 고정 작업 바는 DOM 존재가 아니라 실제 클릭·확대 상태로 검증한다

## 적용 범위와 비적용 조건

편집기 안에 bottom sticky 작업 바를 추가하거나 높이가 변하는 비교·경고 영역을 배치할 때 적용한다. 독립된 스크롤 영역 바깥의 일반 하단 바에는 같은 오버레이 조건이 없다.

## 관측 사실과 영향

초기 시각 QA에서 작업 바가 펼친 수정 Diff를 덮었다. 200% CSS 확대에서는 summary가 DOM에 존재해도 작업 바가 포인터를 가로채 클릭이 실패했고 버튼이 오른쪽으로 9px 넘쳤다. 게시나 데이터 손실은 없었다.

## 근본 원인·기여 요인·근거

bottom sticky는 자연스러운 마지막 위치보다 위에서 페인트되어 중간 콘텐츠를 덮는다. 화면 폭만 고려하면 확대된 실제 편집 영역 폭을 놓칠 수 있다. fr 트랙의 자동 최소 크기도 버튼 넘침에 기여했다.

## 해결과 예방 control

좁은 편집 영역은 container query로 감지해 일반 하단 배치로 바꾸고, 비교·첨부 열림과 입력 포커스에서도 고정을 해제한다. 버튼 그리드는 minmax(0, …)를 사용한다. 요소 개수·존재 검사에 더해 Playwright 실제 클릭·Tab 이동·확대 상태를 합격 조건으로 둔다.

## 검증

scripts/qa/editor-actions-layout.js를 실제 웹에서 실행해 두 테마와 340/390/1024/1440px의 클릭·Tab·넘침을 검증했다. 200% CSS 확대에서 넘침 없음과 static 배치를 확인했다. CSS 확대를 실제 브라우저 확대나 모바일 소프트 키보드 검증으로 주장하지 않는다.

## 발생 정보

2026-09-07 편의성·테마 계획 Phase 6 통합 QA 중 발견. 최초 오버레이 보완 후 좁은 확대 화면에서도 재현되어 편집 영역 기준 안전 조건을 추가했다.

## 검토와 예외

편집기 레이아웃·버튼 라벨·Diff 구조·브라우저 지원 범위가 바뀌면 같은 시각 회귀를 재실행한다. 네이티브 키보드 검증은 별도이며 면제하지 않는다.
