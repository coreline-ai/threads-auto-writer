# 다크 테마 구현 제안 — Forest Night

작성: 2026-09-06 · 상태: **2026-09-07 구현 완료**

## 추천 방향

현재 에디토리얼 스튜디오의 녹색 브랜드와 레이아웃을 그대로 두고 **짙은 차콜 배경 + 살짝 밝은 편집면 + 세이지 강조색**으로 전환한다. 완전한 검정/흰색 반전, 네온 그린, 불필요한 그림자나 글로우는 사용하지 않는다.

사용자가 선택한 테마만 바뀐다. 작성 내용·문체·LLM 설정·검수·승인·Threads 로그인 상태는 바꾸지 않는다.

## 사용 방식

- 선택: **시스템 / 라이트 / 다크**, 미설정 기본값은 시스템.
- 상단에는 이름 있는 작은 테마 메뉴, 설정에는 동일한 세 가지 선택을 제공한다. 아이콘만으로 현재 상태를 추측하게 하지 않는다.
- 시스템 모드에서만 OS 테마 변경을 따라간다. 수동 라이트/다크를 선택하면 OS 변경으로 덮어쓰지 않는다.
- 선택 직후 화면에 반영하고 재실행 시 복원한다. 테마 전환 때문에 편집기를 remount하거나 커서·스크롤·undo 이력을 초기화하지 않는다.
- 웹과 Extension은 별도 Origin이므로 수동 선호도는 각각 저장된다. 같은 Origin의 다른 창/탭은 저장 이벤트로 반영한다.

## 코드 적용 방식

1. `packages/client-ui/src/style.css`의 색상을 역할별 CSS 변수로 정리한다. 라이트도 같은 토큰 이름을 사용한다. 단순한 마지막 줄 다크 override 누적으로 해결하지 않는다.
2. 실제 테마는 `html[data-theme="light|dark"]`에 적용한다. 시스템 선호는 별도로 보관하고 `color-scheme`도 실제 테마와 일치시킨다.
3. 헤더·편집기·버튼·후보·검수·알림·Diff·이미지 입력·캘린더·설정에 고정된 흰색과 밝은 경고색을 모두 점검한다. SVG는 `currentColor`를 유지한다.
4. `apps/web/src/web.css`의 헤더 배경도 공통 토큰으로 바꾼다. 테마별 폭·간격·글꼴 크기 변경은 하지 않는다.
5. 스타일은 테마 전환에 맞춰 즉시 갱신한다. 본문 전체의 긴 색상 애니메이션은 추가하지 않는다. 사진/첨부물에 CSS 반전 필터를 적용하지 않는다.

## 초기화·저장 설계

- `appearance.ts`에 선호도 검증, OS 모드 결정, DOM 적용, 변경 구독을 모은다. 상태 원천은 테마 전용 `localStorage` 키 `threadflow.appearance` 하나다. Dexie와 이중 원천을 만들지 않는다.
- 저장 값은 `system|light|dark`만 허용한다. 읽기 실패/잘못된 값은 시스템으로 돌아가며 본문 DB를 건드리지 않는다.
- 저장이 차단돼도 현재 탭에서는 테마를 사용할 수 있게 하고 재실행 보관 실패는 알린다. 인증 키·계정 정보는 저장하지 않는다.
- Export에는 비밀이 아닌 테마 선호를 포함한다. 전체 데이터 삭제 시 테마 키도 삭제하고 시스템 기본값으로 복귀한다. IndexedDB 삭제만 하고 설정이 남지 않게 통합 테스트한다.
- React와 무거운 앱 번들 전에 동작하는 작은 **공통 외부 초기화 asset**을 웹/Extension 양쪽에 제공한다. Extension에 인라인 스크립트나 `unsafe-inline`을 추가하지 않는다.
- CSS는 초기 attribute가 없을 때도 OS 선호 기반 기본값을 제공한다. 저장 선호를 적용하는 asset의 실제 로드 순서는 두 production HTML과 첫 paint 캡처로 검증한다. 단순 `useEffect`만으로 첫 밝은 화면 깜박임을 해결했다고 주장하지 않는다.
- 새 UI 라이브러리·외부 서비스·추가 Chrome 권한은 필요하지 않은 설계를 우선한다. 번들 연결 방식은 현재 Vite/WXT 산출물에서 확인한다.

## 가독성 검증

단색 sRGB 상대 휘도로 계산한 후보 조합이다. 투명도·hover·disabled·실제 합성 배경을 포함한 UI 접근성 검증 완료를 뜻하지 않는다.

| 조합                       | 계산 대비 |
| -------------------------- | --------: |
| 본문 / 표면                |   13.48:1 |
| 보조 글자 / 표면           |    7.28:1 |
| 보조 글자 / 입력 배경      |    6.52:1 |
| 주요 버튼 글자 / 버튼 배경 |    9.72:1 |
| 링크 / 표면                |    9.46:1 |
| 입력 경계 / 입력 배경      |    3.50:1 |
| 포커스 / 표면              |   11.54:1 |
| 오류 글자 / 오류 배경      |    8.47:1 |
| 경고 글자 / 경고 배경      |    8.12:1 |

프로젝트 검증 목표는 일반 본문 4.5:1 이상, 필수 경계·포커스 3:1 이상이다. disabled 버튼의 기존 전역 opacity를 그대로 상속하지 말고 합성 결과와 상태 식별성을 별도로 검토한다. 오류/승인은 문구와 상태 이름을 유지해 색에만 의존하지 않는다.

## 구현 순서와 합격 기준

- 토큰 정리 → 초기화/저장 → 테마 선택 UI → 상태별 대비 → 두 앱 시각 회귀 순서.
- 340/390/1024/1440px, 시스템/수동 테마, 두 앱의 작성/보관함/캘린더/설정을 확인한다.
- 미설정·저장값 있음·저장 차단·OS 변경·다른 탭 변경·DB 로딩 지연·새로고침·전체 삭제를 검증한다.
- 테마만 바꿀 때 본문/선택/승인 hash/undo가 동일한지 확인한다.
- 이미지가 없는 대기 화면뿐 아니라 생성 중·실패·검수 차단·승인 완료·수정 Diff·빈 보관함도 캡처한다.
- 기존 라이트 테마와 웹 2열·Extension 1열 레이아웃을 유지한다.

개발 순서와 체크리스트는 [편의성·테마 개발 계획](../dev-plan/implement_20260906_225905.md)에 연결한다. 실제 적용과 검증 결과는 [구현 검토](convenience-theme-review.md)에 기록했다.
